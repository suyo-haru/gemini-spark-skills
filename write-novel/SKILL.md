# write-novel

本文の直前にHTMLコメント（`<!-- -->`）で空間設計やキャラクターの思考過程を直接出力することで、説明過多を防ぎ人間味と深みのある小説を執筆するスキル。

## いつ使用するか

- ユーザーが小説、ライトノベル、短編ストーリーの本文執筆を依頼したとき
- プロットや設定資料をもとに具体的なシーンや会話を書き起こすとき
- 既存の原稿の続きや、特定シーンの加筆・書き下ろしを求められたとき

## 執筆手順とフォーマット

### 1. 出力形式の原則（直接記述）

小説本文および思考プロセス用のHTMLコメント（`<!-- -->`）は、コードブロック（` ``` `）で囲まず、通常のMarkdownテキストとして直接出力する。
これにより、通常のレンダリング画面ではコメントが自動的に非表示となり、読者は純粋な小説として読むことができる。同時に、生成時のコンテキストおよび後続の推敲スキル（`review-novel` 等）への設計図として機能する。

### 2. シーン設計コメント `[Scene]` の記述

場面の開始時や、空気感・状況が変化するタイミング（数段落に1回程度）で、本文の直前に罫線(`***`) と、以下のHTMLコメントとを記述する。

- **状況**: 現在の場所、時間帯、周囲の環境。
- **五感/カメラ**: 視点人物の視線の動き、音、匂い、肌触り、温度感など。会話が続いて背景が消える「白い部屋症候群」を防ぐために必ず具体化する。
- **読者演出**: このブロックで読者に与えたい空気感（緊張、違和感、日常のゆるさなど）と、そのために「あえて直接言葉で説明せずに描写だけで匂わせること（Show, Don't Tell）」。特に、実際に見た・起きた「◯◯らしい」「◯◯(できる)ようだ」といった **伝聞的な・主観的な表現は極力使わない** 。
- **一時的に登場するキャラクターの設定** (存在する場合のみ): このブロック以降で登場するキャラクターの簡易的な設定。人物の場合は名前、見た目、メインキャラクターとの関係、(関係が知り合い以上の場合は)背景設定など。

### 3. キャラクター思考コメント `[Char: 名前]` の記述

感情が動くセリフやアクションの直前に、以下のHTMLコメントを記述する。なお、テンポを重視する短い掛け合いや単なる相槌では省略してよい。
メインキャラクターだけでなくモブキャラなど一次的に登場するキャラクターや、現在の場面には存在しないが、文面や動作があるもの(例:スマホや手紙のメッセージやポルターガイストの動きなど)にも適応される。

- **状態** (その出来事が現在でない場合): そのときの状況(キャラクターから見た視点で)
- **認識/本音**: その出来事や相手の言動をどう受け止めたか、心の中で本当に思っていること（内面）。**文面にはキャラクターの生の性格/表現を反映すること。**
- **表出/行動**: 本音を隠す、あるいは間接的に伝えるために、あえてどのような態度・声色・視線・手元の仕草・言葉を選ぶか（内面と表出のギャップ）。ギャップがほとんどない場合は省略しても良い。

### 4. 本文の執筆と変換

直前のHTMLコメントの設計をコンテキストとして受け止め、小説の本文を出力する。

- コメント内で使用した「焦る」「気味が悪い」「悲しい」「嬉しい」といった直接的な感情語や状態語は、直後の本文ではそのまま使用しない。
- コメントで定義した「視線の動き」「身体反応」「風景の見え方の変化」「少しズレたセリフ」へと変換して描写する。
- 日本語の小説作法に従い、地の文の段落頭には全角スペース（`　`）を入れ、会話文（`「」`）と地の文のバランスを整える。

## 記述イメージ

※以下は構造を示すための例であり、実際の出力時はコードブロックで囲まずに直接出力すること。

```markdown

*****
<!-- ↑直前に本文がある場合に挿入 ->

<!-- [Scene]
状況: 放課後の昇降口。西日が差し込み、遠くで運動部の掛け声が響いている。
五感/カメラ: 視線は下駄箱から自分の足元へ。夕方の少し埃っぽい空気と上履きのゴムの匂い。
読者演出: 穏やかな日常の中に「ほんの少しの奇妙な違和感」を混ぜる。「不思議だ」とは直接書かず、視覚的なズレの描写だけで読者に気づかせる。
-->
　西日が斜めに差し込む昇降口は、浮遊する埃がやけに白く光って見えた。
　下駄箱の扉を開けようとして、ふと視線が足元に吸い寄せられる。さっき教室を出る前にきっちり結び直したはずの右足の靴紐が、まるで誰かが悪戯で引っ張ったみたいに、だらりとタイルの上に垂れ下がっていた。

<!-- [Char: 静]
認識/本音: 今、紐の先端がピクリと縮んだ気が気が…正直かなり気味が悪いけど、隣にいる友人には絶対に気づかれたくないし…。
表出/行動: 動揺を隠すために、あえて普段通りの少し冷めた声色で無関係な話題を振る。靴紐を踏まないように半歩だけ後ろに下がる。
-->
「……ねえ、購買のパン、今日の限定なんだっけ」
　私はつま先をさりげなく影に引き込みながら、隣でスマホを覗き込んでいる友人に声をかけた。
```

## 付属スクリプト

### `scripts/wordcount.py`

Markdownファイルの文字数・空白文字数・段落数を集計する。

#### 実行例

```bash
python wordcount.py document.md
python wordcount.py document.md --line 1-5
python wordcount.py document.md --line 10
```

#### 出力例

```bash
ファイル: sample.md
対象範囲: 全行
文字数（記号・空白・改行を含む）: 48
文字数（HTMLコメント除外）     : 35
WhiteSpace文字数               : 12
WhiteSpace文字数（コメント除外）: 10
段落数（CommonMark）           : 2
```

集計仕様:
* 入力はUTF-8（BOM付き可）。BOMは除き、CRLF / CRはLFに統一する。
* 文字数はPythonのlen()によるUnicodeコードポイント数。Markdown記号、HTMLタグ、空白、改行を含む。結合文字・絵文字は表示上の1文字と一致しない。
* WhiteSpaceの文字数はstr.isspace()で判定する。全角スペース、タブ、LF等も含む。
* コメント除外は、MarkdownでHTMLとして認識された<!-- ... -->が対象。コード内やエスケープされた表記、HTML属性値内の文字列は残す。閉じていないHTMLコメントブロックは、そのブロックの末尾まで除外する。
* 段落はCommonMarkのparagraph_openを数える。リスト・引用内も含み、見出し、コードブロック、HTMLブロックは含めない。
* 行番号は1始まり・両端を含む。全文を解析してから指定範囲を集計する。範囲に一部でもかかる段落を1段落と数えるため、範囲別の段落数は加算不可。

## 注意事項（Gotchas）

- **コードブロック化の禁止**: ユーザーから「コメントが見えるようにコードブロックで出力して」等の明示的な指定がない限り、絶対にコードブロック（` ``` `）で囲まないこと。
- **コメント内の言葉を本文でなぞらない**: コメントで「動揺を隠すために話題を逸らす」と書いた直後の本文で、「私は動揺を隠すために話題を逸らした」と書いてしまっては意味がない。コメントはあくまで設計図であり、本文にはその結果の現象（セリフや仕草）のみを出力すること。
