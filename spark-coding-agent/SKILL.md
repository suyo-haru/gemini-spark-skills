# spark-coding-agent

Extract an uploaded base environment archive, set up dependencies, develop a modular application according to user specifications, and package the clean source code for delivery.

## When to Use

- Explicitly triggered by the user with `@spark-coding-agent`.
- Tasks that require unpacking a base environment ZIP/TAR into `/tmp` and expanding it into a complete multi-file project (Node.js, Python, etc.).

## Steps

1. **Extract Archive**
   - Locate the specified ZIP/TAR archive provided by the user.
   - Extract its contents directly into `/tmp` (e.g., `/tmp/<project_name>`).
   - Inspect the extracted structure to detect project configuration (e.g., `package.json`, `requirements.txt`, `pyproject.toml`).
   - If user also provided, locate and extract additional runtime binary and include directory to `$PATH`. (e.g., `export $PATH=/tmp/<runtime-path>/bin:$PATH`)

2. **Environment & Dependency Setup**
   - Identify the runtime environment (Node.js or Python).
   - If you need to install required dependencies within the environment: Stop and ask user to send libraries as ZIP/TAR.

3. **Develop the Application**
   - If the project has `AGENTS.md`, you should read it first.
   - Implement or inspect the application requested by the user.
   - Maintain proper architectural separation across multiple modules, components, configuration files, and asset folders.
   - Test and verify execution within the environment where applicable.

4. **Package and Deliver Clean Artifact**
   - If the project has git repository:
     - Add file(s) and create commit with message: `[<Add|Delete|Fix|Fmt|Chore>] <short description of changes, in Japanese>`. You don't have to create or change branch.
     - Produce `<feature-name>.patch` file by `git diff`.
  - Otherwise:
    - Exclude generated dependency directories and caches:
       - For Node.js: Exclude `node_modules`, build caches (`.next`, `.turbo`, `dist` if regenerated by build).
       - For Python: Exclude `.venv`, `venv`, `__pycache__`, `.pytest_cache`, `.eggs`, `*.pyc`.
       - Exclude system junk (e.g., `.DS_Store`).
     - Archive the cleaned project files into a new ZIP/TAR file. (Select as same type as the user provided one.)
       - For TAR archive: Add `--owner=0 --group=0` to exclude uid/gid.
   - Upload the PATCH file or ZIP/TAR file to Google Drive or generate an accessible download link for the user.
   - Do NOT produce a single file on inline.

## Important Notes

- The version of Node.js in this environment is outdated (v18). Consider using the user provided one (if they did).
- If you need to run headless chromium, you have to use **`127.0.0.2`** for local IP address or you will blocked by policy.

## Gotchas

- Never pack heavy dependency trees (`node_modules`, `.venv`) into the final PATCH/ZIP/TAR file to keep delivery lightweight and reproducible.
- Ensure all relative paths and import statements remain consistent after archive packaging.
- Check file permissions and executable flags on scripts before bundling.
